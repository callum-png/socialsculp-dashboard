How should Mission Control talk to OpenClaw?

Now that we know the VPS setup, here are three realistic approaches

A

SSH Relay Only

Dashboard API routes SSH into the VPS on every request, runs openclaw CLI commands (health, cron list --json, agents list), and returns the JSON. Simple, no VPS changes needed.

Dashboard click → Next.js API route → SSH exec → openclaw cron list --json → JSON back
Dashboard click → Next.js API route → SSH exec → openclaw health → parse + return
Dashboard click → Next.js API route → SSH exec → tail -100 /tmp/openclaw/*.log → stream

Pros

  • Zero changes to OpenClaw or VPS
  • CLI already has --json output
  • Full ad-hoc control (restart, kill, etc.)
  • Fastest to build

Cons

  • Every request = new SSH connection (~200-500ms latency)
  • No real-time push — only updates when you look
  • SSH key must be stored on Vercel (env var)
B

Tailscale Direct + Gateway WebSocket

Your VPS already runs Tailscale. Expose the OpenClaw gateway on the Tailscale network, then connect the dashboard directly via WebSocket for real-time data. No SSH needed.

Vercel → Tailscale Funnel/HTTPS → ws://100.x.x.x:18789 → OpenClaw Gateway
Real-time: agent events, cron status, session updates streamed live

Pros

  • Real-time WebSocket connection
  • No SSH keys to manage
  • Uses OpenClaw's native protocol
  • Lowest latency

Cons

  • Requires Tailscale Funnel or proxy for Vercel to reach VPS
  • Gateway auth/token management needed
  • More complex networking setup
  • Vercel serverless can't hold persistent WebSocket
C

SSH Relay + Polling ★ Recommended

SSH relay for all data + controls (same as A), but the dashboard polls every 30-60s on the status page for near-real-time feel. Cron run history and logs read from VPS files. Client-side polling with SWR gives a live dashboard feel without WebSocket complexity.

Auto-poll (30s):
  SWR → /api/openclaw/status → SSH → openclaw health + cron list --json

On-demand:
  Button → /api/openclaw/logs → SSH → tail -200 /tmp/openclaw/*.log
  Button → /api/openclaw/cron/trigger → SSH → openclaw cron trigger <id>
  Button → /api/openclaw/restart → SSH → systemctl --user restart openclaw-gateway

Token/cost tracking:
  SSH → parse log files for model usage → aggregate in dashboard

Pros

  • Near real-time feel with SWR polling
  • Zero VPS changes — all via SSH + CLI
  • Full control panel (restart, trigger, kill)
  • Pragmatic — can upgrade to WebSocket later
  • Works on Vercel serverless (no persistent connections)

Cons

  • SSH key in Vercel env vars
  • 30s polling delay (not instant)
  • Each poll = SSH connection overhead
