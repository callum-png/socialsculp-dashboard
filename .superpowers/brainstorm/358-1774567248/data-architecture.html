How should Mission Control get data from OpenClaw?

Pick the communication pattern between your dashboard and the VPS

A

OpenClaw Reports In (Push)

OpenClaw pushes heartbeats, task logs, and token usage to the dashboard via API. You see live status without touching the VPS.

VPS (OpenClaw)
└─ Every 60s: POST /api/openclaw/heartbeat
└─ On task start/end: POST /api/openclaw/tasks
└─ Hourly: POST /api/openclaw/usage {tokens, cost}

Dashboard (Mission Control)
└─ Reads from DB, displays in real-time

Pros

  • Real-time updates
  • No SSH keys on dashboard server
  • Works even if dashboard is down (queues up)

Cons

  • Requires adding a reporting client to OpenClaw
  • Can't run ad-hoc commands on VPS
B

Dashboard Reaches Out (Pull)

Mission Control SSH's into the VPS on-demand to check logs, process status, and cron output. You trigger inspections manually.

Dashboard (Mission Control)
└─ Button click: SSH exec "systemctl status openclaw"
└─ Button click: SSH exec "tail -100 /var/log/openclaw"
└─ Button click: SSH exec "cat /tmp/openclaw-usage.json"

VPS (OpenClaw)
└─ Passive — just responds to SSH commands

Pros

  • No changes needed on OpenClaw side
  • Full ad-hoc access (run any command)
  • Simple — just SSH

Cons

  • SSH keys stored on Vercel (security risk)
  • Not real-time — only updates when you look
  • Latency on each request
C

Hybrid (Push + On-Demand) ★ Recommended

OpenClaw pushes heartbeats & task updates automatically. You can also trigger SSH commands from Mission Control for deep inspection, restarts, etc.

VPS (OpenClaw) → Dashboard
└─ Heartbeat every 60s (alive/dead/working)
└─ Task events (started, completed, failed)
└─ Token/cost usage reports

Dashboard → VPS (on-demand)
└─ View live logs
└─ Restart services
└─ Kill runaway tasks
└─ Run diagnostics

Pros

  • Best of both worlds — passive monitoring + active control
  • Always know if OpenClaw is alive (no manual checking)
  • Can intervene when something goes wrong

Cons

  • More to build (both push client + SSH relay)
  • SSH key management still needed for on-demand
